# Required Name and Android live workout displays

The user requires a nonblank Name instead of optional First name. Onboarding cannot be skipped. Existing unnamed profiles/drafts remain readable without rewriting records, but app routes require a name before continuing. Remove prominent exercise-provider branding from browsing while retaining the required linked credit and offline license in Settings. Remove in-app update UI/plugins; new versions are distributed normally through Play Store.

The user selected both an Android home-screen widget and a workout notification. They show the original elapsed timer and current exercise, and tapping returns to the existing active workout without creating another. Android host Chronometers render elapsed time without a per-second Flutter/native background service. Permission denial must not affect logging or home widgets. Widgets are user-owned launcher items; inactive/unfinished/idle states replace disappearing widgets. Notification lifetime is tied to the active workout and actual app finishing; backgrounding preserves live displays, while closing preserves the draft. Force-stop/system process death lifecycle delivery is controlled by Android, so draft recovery must not depend on callbacks.

Use one native MethodChannel and private atomic JSON snapshot, with AppWidgetProvider/RemoteViews and a silent notification. No foreground service, sensor permission, alarm, account, network or third-party widget plugin is required. The native snapshot is a display cache, never the authoritative workout database. Dart publishes only durable workout state plus ephemeral explicitly selected exercise focus. The original startedAt value ensures restart-safe elapsed time. Native launch callbacks are buffered through boot and required-name onboarding.

Users may resume a draft or explicitly Save & start new. Save all prior draft sets, including incomplete sets, and create the new draft in one repository transaction; a failed save leaves both unchanged. Flush visible input first. Ordinary close never automatically archives/discards a draft. Schema/CSV remain unchanged.

Verify empty-name bypasses and legacy routing, compact credit/update removal, focus and atomic restart flow, platform method-channel behavior and serialized state sync, Android build and live widget/notification behavior. Check narrow layouts, notification permission denial, cold/warm tap routing, completion/discard cleanup and restart recovery. Native compatibility follows the app's Android floor and launcher capability; widget pin requests are optional and user-confirmed.
